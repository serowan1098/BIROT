# LookIT — Mobile UI/UX Prototype

A **UI/UX design concept and mobile prototype** for a home-security application, built in **Figma**.

> **Status:** Design prototype and product concept. Nothing is implemented, deployed, or released.

---

## Overview

Most home security cameras are something you *watch*. LookIT proposes the opposite: a setup where the camera and speaker work together so you can actually **talk** to whoever is at your door.

The concept uses an existing camera and speaker setup and turns it into a two-way voice interaction point — useful when you're not at home and a visitor, delivery, or unexpected person shows up.

---

## The Concept

**Problem:** A visitor arrives while you're away. A camera shows you a feed, but you can't communicate — you're reduced to watching.

**LookIT's answer:** Voice-first interaction through the speaker.

- A visitor arrives and initiates contact
- You get a voice prompt and respond hands-free
- The AI handles the interaction when you can't answer
- Deliveries and routine visitors can be handled without you being physically present

## How I Approach the Design

1. **Start from the user's real situation,** not the feature list. Who is at the door, and what do they actually need?
2. **Map the flows first.** Visitor arrives → detection → notification → response → resolution.
3. **Voice-first, not video-first.** The audio interaction is the core of the product; the camera feed is supporting context.
4. **Design the failure states.** What happens when the network drops, or the visitor doesn't respond? Those screens matter more than the happy path.
5. **Prototype before building,** so the interaction can be tested before any hardware is involved.

## What I Learned

- Mobile interface design — spacing, hierarchy, and thumb reach on a small screen
- Designing voice interactions, where there is no visual affordance to guide the user
- Translating a real-world problem into a product concept
- User flow thinking: every screen needs an entry, an action, and an exit
- Prototyping in Figma to make an idea testable before it's built
- Writing a concept clearly enough that someone else could evaluate it

## Future Improvements

- A second round of prototyping after user testing
- Accessibility pass for voice-first interfaces (how does it behave without sound?)
- A visual identity and icon set — the current prototype is focused on flow, not branding
- Wireframes for the settings and device-pairing flows
- Define the AI interaction boundaries clearly, so the assistant never over-promises to a visitor
